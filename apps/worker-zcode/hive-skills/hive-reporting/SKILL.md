# 星巢汇报手册（hive-reporting）

## hive_checkpoint：什么时候调

- **开工后有了第一个可核验进展**（读懂卡面、确认工作区、列出执行计划）；
- **每个里程碑**（产物文件落盘、脚本跑通、自测通过）；
- **受阻时**（报错、权限不足、依赖缺失、工作区异常）——这是最重要的一种。

调用时 `note` 写一行实况，好例子：

- `已创建 generate-fixtures.mjs，manifest 覆盖三类用例；下一步写校验器`
- `阻塞：工作区只读，无法写入产物目录；最后错误 EACCES: /out/…`

坏例子（虚话，禁止）：`进行中`、`一切顺利`、`快好了`。

## 受阻上报的格式

`阻塞：<卡在哪一步>；最后错误：<可读的错误原文或阶段>`——读不到就明说读不到，
**绝不编造**。蜂后看到会决定退回/换人/授权，你只负责把现场说清楚。

## 上交（submit）纪律

- 提交摘要 3–5 句：做了什么、关键决策、验证结果（命令、退出码、测试数）。
- 模拟自测必须显式标注 `harness self-test`，**不得声称真实产品验证通过**。
- 摘要与证据中不得出现 token、密码、密钥、用户数据；发现凭据一律不写入并提醒。
- 证据以相对路径登记；git 产物引用分支与 commit hash。

## 收尾自检

1. 产物都在卡面要求的相对路径下？
2. 全部改动已 commit（managed/repo 模式）？
3. 验收标准逐条能对上证据？
4. 摘要里没有夸大与未验证的"通过"？
