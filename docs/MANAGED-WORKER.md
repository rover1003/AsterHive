# 托管工蜂使用说明

托管工蜂（Managed Worker）是在星巢为单张任务卡准备的一次性工作区内执行工作的工蜂。工作区由服务器派驻和管理，任务产物应按任务卡指定的相对路径保存；任务完成后通过该任务分支提交，工作区随后可能被销毁。

## 零外部 CLI 依赖

托管工蜂的执行入口由星巢工作进程提供，不要求使用者另外安装或配置外部 AI 命令行工具。领取任务后，工蜂直接在派发的工作区内读取任务卡、修改指定文件并按要求提交。不要为了启动工蜂而自行安装依赖或访问宿主机凭据；若任务本身确实需要额外工具而卡面未授权，应报告阻塞。

## 内置 Pi 执行内核

工蜂通过内置的 Pi 执行内核完成任务循环：理解任务要求，检查工作区上下文，在允许范围内编辑文件，运行适当的检查，并在适用时将改动提交到任务分支。Pi 内核提供执行所需的代理能力，因此托管环境不依赖单独安装的 Pi CLI。遵守任务卡中的验收标准、文件范围和保护路径约束，不扩大改动范围。

## 双通道接入

星巢提供两类接入路径：

- **服务器派驻（托管模式）**：服务器为任务创建一次性工作区并启动工蜂，适合由任务卡驱动的受控执行。工蜂在工作区内完成产物，并通过任务分支提交回传。
- **本地接入**：在支持的本地工作环境中，通过星巢提供的接入入口与工蜂交互，适合开发者在自己的工作流中使用。该路径仍应遵循任务授权和仓库边界；托管模式所需的工具不应被误认为本地必须额外安装的 CLI。

具体可用入口由当前星巢部署与任务配置决定；按界面或派发信息提供的入口操作，不要猜测或自行构造命令。

## 一键命令

在受支持的接入界面中使用星巢提供的一键启动/派驻操作，即可建立执行会话并将任务上下文交给内置 Pi 内核。托管任务通常由服务器自动完成工作区准备和启动，无需手动启动外部 CLI。启动后确认当前任务编号与工作区，按任务卡完成工作；提交前检查改动只涉及授权文件，提交后如实汇报产物位置和验证结果。

> 一键操作的名称及可用参数可能随星巢部署版本变化，请以当前界面或服务器下发的操作说明为准。不要在文档或提交中记录凭据、密钥或用户敏感数据。
